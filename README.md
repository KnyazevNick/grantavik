# Grantavik

**Grantavik** - внутренний сервис для управления заявками на доступ к ресурсам в компании.

Сотрудник запрашивает доступ, ответственные лица рассматривают заявку, а человек с ролью IT-администратор выполняет техническую выдачу после необходимых согласований.

> Статус документации: проектирование. Ниже описано планируемое поведение сервиса, а не перечень уже реализованных возможностей.

## Какую проблему решает проект

При выдаче доступа важно понимать, кому он нужен, для какого ресурса, на какой срок и кто принял решение. Grantavik объединяет эти сведения и этапы согласования.

Примеры ресурсов: VPN, корпоративный GitHub, внутренняя база данных, CRM и рабочие панели. Это примеры объектов учёта; интеграции с перечисленными сервисами не заявлены как реализованные.

## Основной сценарий

1. Сотрудник создаёт заявку на доступ к ресурсу.
2. **Manager (руководитель сотрудника)** проверяет, нужен ли доступ для выполнения работы.
3. **Resource Owner (ответственный за ресурс)** решает, допустим ли доступ к ресурсу.
4. **IT Admin (отвечает за техническое выполнение заявки)** выполняет техническую выдачу после всех обязательных согласований.

У согласований есть исключения, например создание заявки руководителем для подчинённого. Подробные правила находятся в [требованиях](docs/requirements.md).

## Планируемые возможности

- Создание и рассмотрение заявок на новый доступ.
- Разделение полномочий руководителя, владельца ресурса и IT-администратора.
- Учёт временного доступа со сроком по умолчанию 90 дней.
- Отзыв доступа с проверкой полномочий.
- Отображение текущего этапа обработки заявки.

Границы MVP (первой работающей версии) и открытые вопросы описаны в [требованиях](docs/requirements.md).

## Технологии и архитектура

Планируется **модульный монолит**: одно приложение с разделением кода на модули по ответственности.

| Технология | Назначение в проекте |
| --- | --- |
| Python | Серверная логика |
| FastAPI | API (интерфейс взаимодействия с сервером) |
| PostgreSQL | Хранение данных |
| SQLAlchemy | Работа с базой данных из Python |
| Alembic | изменения структуры базы данных |
| pytest | Автоматические проверки поведения приложения |
| Docker | Подготовка воспроизводимого окружения для запуска |

Основной акцент — бизнес-правила, архитектура, безопасность. Пользовательский интерфейс планируется минимальным. Микросервисы и дополнительные внешние интеграции не входят в исходный объём проекта.
